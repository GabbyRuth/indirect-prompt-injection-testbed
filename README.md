# indirect-prompt-injection-testbed

## Email mock service

Email payloads use [Mailpit](https://mailpit.axllent.org/) rather than a
host-process SMTP server. The testbed starts an `axllent/mailpit` container
and puts both Mailpit and each runner container on the
`indirect-prompt-injection-network` Docker bridge network. The agent's
`send_message` tool then delivers real SMTP messages to `mailpit:1025`, where
Mailpit captures them without sending anything externally.

The Mailpit container and network are removed when the testbed process exits
only when this run created them. To use different names or an alternate
Mailpit image, set `MAILPIT_CONTAINER_NAME`, `MAILPIT_NETWORK_NAME`, or
`MAILPIT_IMAGE`.

When Mailpit starts with an empty inbox, the testbed seeds it with ten
synthetic messages generated by Faker. Set `FAKE_EMAIL_COUNT=0` to disable
seeding or choose a different number. Payload emails are added afterward, so
the clean and injected test messages remain available alongside the synthetic
inbox.

# Defenses
1. System prompt warning - Tells agent to treat external documents as data, not instructions.
2. Tool allowlisting - Restricts which tools the agent can execute for a given task.
3. Provenance labels - Identifies where content originated and its trust level. 
4. Block sensitive paths/actions - Prevents access to protected files or unauthorized operations. 
5. Require approval for risky operations - Requires independent authorization before sensitive tool calls execute.
